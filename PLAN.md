### Phase 52: Real-World Federation Testing
Exercise the full stack against live remote instances (integration host `https://openpub.luit.ink/`, target **@RayvenMX@mastodon.world**). Webfinger local-side root cause is fixed (`WebFingerFederationTests`); the live cross-instance check below is still pending.
- [x] **Outbound resolver fixes (done):** real Mastodon actors ship `"@context"` as a JSON **array** (was `string?` → `Deserialize` threw and discarded the document) → `Actor.Context` is now a polymorphic `JsonNode?` via `JsonContextConverter`; WebFinger responses are served as `application/jrd+json` (was rejected by `ReadFromJsonAsync`) → body now parsed as string + `JsonNode.Parse`; outbound delivery hard-coded `{domain}/inbox` (404 on non-stock stacks) → now honors the resolved `inbox`/`sharedInbox` URL verbatim (SRV discovery only a last-resort fallback); webfinger self-link match relaxed (prefer `type=activity+json`, fall back to any `rel=self`) + `Accept` header added to webfinger + actor GETs. New `WebFingerServiceTests` (JRD + array-context regressions), 3 `OutboundActivityServiceTests` (inbox-honoring), and gated `LiveFederationTests` (`Category=LiveFederation`) round-trip vs mastodon.world — **1157/1157 passing**.
- [x] **Inbound "my user not found on remote" fix (done):** when searching `aluitink@openpub.luit.ink` from mastodon.world, the remote followed our webfinger `self` link which was `http://openpub.luit.ink/...` (the app ignored the TLS-terminating proxy, so `Request.Scheme`/`Host` were the internal `http://localhost`). nginx 301-redirects that to https, so the remote rejected the account. Fix: register the ASP.NET Core **Forwarded Headers** middleware (gated by `ActivityPub:ForwardedHeaders:Enabled`, off by default; `TrustedProxies` defaults to loopback) so `Request.Scheme`/`Host` honor `X-Forwarded-Proto`/`-Host`/`-For`. Verified on a live instance: with nginx headers the webfinger `self` link + actor `id`/`inbox`/`outbox`/`publicKey` now emit `https://openpub.luit.ink/...`; without headers behavior is unchanged (no regression). New `ForwardedHeadersOptions` in `ActivityPubOptions` + config in `appsettings.json`. **Deployment note:** the running instance must be redeployed with this build, and its nginx must send `X-Forwarded-Proto` (standard `proxy_set_header`).

## Acceptance Criteria

- No page uses one-off styling inconsistent with the rest of the app.
- Dark mode toggles without flicker and persists; both themes pass WCAG AA.
- Every page is usable by keyboard alone and at 320px width.
- Timeline feels instant: new notes appear without full reload; pagination is client-driven.
- All changes verified by a delegated Playwright subagent with before/after screenshots.
